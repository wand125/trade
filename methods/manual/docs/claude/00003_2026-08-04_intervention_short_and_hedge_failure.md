## 訂正: ロット単位

本口座は1ロット=1,000通貨(マイクロ)。USDJPY 100ロット=10万ドルで**1pip=1,000円**。最大建玉140ロット(約14万ドル、証拠金約40万円に対しレバレッジ約55倍)。[[00002]] の初版にあった「1pip≈10万円」「隠れコスト4.9万円」は誤り。

## 介入狙いフェーズの再評価(7/13〜7/30)— 形は合理的、総量は過大だった

- 162.41 / 163.16 / 163.68 に20ロットずつ、計60ロット(6万ドル)のショート。段階エントリーの形は妥当
- ただしサイズは過大(訂正 2026-08-04: 初版の「100pips逆行で−12,000円」は誤り。正しくは60ロットで**100pips逆行=−60,000円(残高の30%)**。ピークを164円前後と仮定すると最大含み損は約−55,000円=残高の27%に達していたと推定)。生還したのは逆行が約1.4円で止まったため。適正サイズの導出は [[00004]]
- 待機コスト(スワップ)は期間合計**−14,191円**(約−24円/ロット/日)と軽微
- 7/30の急落で+202,275円。カタリスト待ちのイベントドリブン戦略として**構造は成立していたが、サイズ設計だけが欠けていた**
- 問題は「ナンピン」ではなく、**イベント成就後に戦略が終わらなかったこと**。介入狙いのシーシスは急落した時点で消滅しているのに、同じ夜に底値圏158.6を再びショートし、翌日は根拠のない100ロットの売買に移行した

## 最終夜の解剖(7/31、時刻はサーバー = JST−6)

deal履歴から復元したポジション推移:

| 時刻(JST) | 出来事 | 結果 |
|---|---|---|
| 16:29(22:29) | 100ロット買い @159.64 | ネットロング100 |
| 17:11(23:11) | 40ロット買い @159.30 | ネットロング140 |
| 18:57(0:57) | **ヘッジのショート100 @159.19** | 両建て成立 |
| 18:59(0:59) | そのショートが**2分で決済**(+3pips) | **裸のロング140に戻る** |
| 20:28(2:28) | **再びヘッジのショート100 @158.76** | 両建て成立 |
| 20:45(2:45) | そのショートが**17分で決済**(−13pips) | **裸のロング140のまま就寝** |
| 23:33(5:33) | ロング100を強制決済 @157.94 | −169,800円 |
| 23:35(5:35) | ロング40を強制決済 @157.87 | −57,200円(週末クローズ25分前) |

**ヘッジは2回とも建った直後に自動決済されている。** 1回目+3pips、2回目−13pipsという浅い値幅での決済は、ショート注文に既定のTP/SLが付いたまま発注された可能性が高い(発注画面のTP/SL欄に前回値が残っていた等)。本人は両建てが維持されていると認識して就寝し、実際には140ロットのロングが無防備のまま160→157.9の下落を受けた。

## 構造的な考察

1. **両建てによるリスク回避は、決済と経済的にほぼ等価で、失敗モードだけが多い。** ネットエクスポージャをゼロにしたいなら決済すれば確実に達成でき、確認も不要。両建ては「建ったか」「維持されているか」の運用リスクとスプレッド・スワップの二重払いを追加する
2. **確認の不在が直接死因。** 両建て後にポジション一覧(ネット数量)を確認していれば、18:59 / 20:45 の時点で異常に気づけた
3. サイズの自覚(100ロットは不適切)があっても、**縮小ではなくヘッジで対処した**ことが事故の入口になった。不適切なサイズへの正しい対処は減らすこと
4. 強制決済は週末クローズ25分前の最悪の流動性で執行された([[00001]] の候補5と同件)

## 昇格候補(本人の判断待ち)

1. principles: リスクを消したいときは両建てではなく**決済する**
2. principles: サイズが大きすぎると気づいたら、ヘッジではなく**その場で減らす**
3. principles: 就寝前にポジション一覧でネット数量を確認する(0のつもりなら0であることを見る)
4. principles: イベント狙いの取引はイベント成就で終了。再エントリーには新しい根拠を要する
5. mistakes: 発注画面に残った既定TP/SLでヘッジが即時消滅するパターン(実例: 7/31 18:59・20:45)
6. playbook候補: 介入待ちショートは「数週間の逆行に耐えるサイズ(例: 100pips逆行=残高の6%以内)+スワップ実測」で設計する — 7/13〜7/30の実績が雛形
