# manual Docs Index

人(自分)が裁量でトレードするときの知見をまとめる場所。パスはすべてリポジトリルート基準で表記する。

自動化された検証手法(entry_ev、swing_eval)と違い、この手法の主体は人。だからこそ記録を残し、記録から知見を抽出して蓄積するサイクルを回す。

## 構成

- `principles.md`
  トレードで必ず守る原則。資金管理、リスク上限、やらないことのリスト。

- `market_hours.md`
  閉場・オープン時刻(実測ベース)。持ち越し判断とエントリー回避時間帯の基礎。

- `campaign.md`
  現在の作戦(本人が記述)。シーシス・サイズ計画・無効化条件・追加の条件。Claudeへの相談はこれを共通コンテキストとして行う(体制の詳細はリポジトリルートの CLAUDE.md)。

- `playbook.md`
  セットアップ集。どういう相場状況で、何を根拠に、どうエントリー・決済するかの型。

- `mistakes.md`
  失敗パターンと対策。同じ失敗を繰り返さないためのカタログ。

- `journal/`
  トレード記録。ファイル名は `00001_YYYY-MM-DD_slug.md` の通し番号形式にする。1トレード(または1セッション)ごとに、テンプレートに沿って事実と判断を記録する。**見送り・検討のみの場合も記録する**(templates/skip_entry.md。機会損失を正直に計上し、原則自体のEVを検証可能にするため)。

- `claude/`
  Claude によるデータ分析・考察レポート(番号付き)。**本人の考察とは分けて管理する。**

- `templates/`
  記録用テンプレート。

## 知見の帰属ルール

- `principles.md` / `playbook.md` / `mistakes.md` / `journal/` は**本人の考察・判断だけ**を書く場所。Claude は直接書き込まない
- Claude の分析・考察は `claude/` に番号付きレポートとして残す。各レポート末尾に「昇格候補」を列挙する
- 本人が採用を決めた候補だけを自分の言葉で principles 等へ書き、出典として claude レポート番号(例: `claude/00002`)を添える
- 実測データそのもの(market_hours.md 等)は事実のリファレンスとして共用し、冒頭に測定方法と測定者を明記する

## 運用サイクル

1. トレード前に `principles.md` と `playbook.md` を確認する。
2. トレードしたら、その日のうちに `journal/` へ記録を残す(勝ち負けに関係なく)。
3. 記録がたまったら見直し、繰り返し現れる気づきを昇格させる:
   - 守るべきルールになったもの → `principles.md`
   - 再現できる型になったもの → `playbook.md`
   - 繰り返している失敗 → `mistakes.md`
4. 昇格した知見には、根拠となった journal エントリの番号を添える。

## 他の手法との関係

- entry_ev の研究知見(汎化原則、バックテストの落とし穴)は `methods/entry_ev/docs/` を参照。
- 相場スナップショットや口座状況の確認は swing_eval のブリッジ環境(`methods/swing_eval/docs/WORK.md`)を使える。
- 裁量トレードの気づきから検証可能な仮説が生まれたら、新しい手法として `methods/<手法名>/` に切り出す。
