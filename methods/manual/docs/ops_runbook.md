## 【標準規定】無効化条件の撤去は常に運用セッションへ委任する(2026-08-11 本人決定)

**本人指示: 「撤去も運用しましょう」** — 作戦ごとに書くのではなく、**すべての作戦に自動的に適用される標準規定**とする。

### 常に委任されているもの(作戦ごとの記載は不要)

| 対象 | 委任 |
|---|---|
| **campaign.md に書かれた無効化条件の判定** | **運用セッションが行う** |
| **無効化成立時の未約定注文の撤去**(`cancel`) | **確認なしで実行してよい** |
| **無効化成立時の作戦のアーカイブ移動と報告** | **確認なしで実行してよい** |

### 委任されないもの(この規定でも変わらない)

| 対象 | 扱い |
|---|---|
| **ポジションを持っている場合の決済** | **作戦ごとの委任表に明記があるときのみ**。なければ報告のみ |
| 新規エントリー・増ロット・ナンピン | **委任外**(いかなる場合も) |
| **SLの引き下げ・撤去** | **委任外**(いかなる場合も) |

**未約定注文の撤去だけを標準委任にする理由**: **撤去はリスクを減らす方向にしか働かない**(注文が消えるだけで、損益は発生しない)。判断を誤って撤去しても失うのは機会だけで、口座は傷つかない。**決済は損益が確定する**ため、標準委任にはしない。

### 実行手順

1. campaign.md の「無効化条件」節を読み、**価格・根拠・時間のいずれかが成立したか**を判定する
2. **判定が微妙なら撤去せず報告する**(境界値は相談セッションへ)
3. 撤去する場合: `create_trade_command.py cancel --symbol <銘柄> --ticket <注文番号> --live --confirm LIVE`。**発行直前に価格を再取得する**
4. 撤去後ただちに**時刻・現値・成立した条件・注文番号**を報告
5. campaign.md へ追記し、**その作戦をアーカイブへ移す**

## 報告様式

### 末尾に必ず付ける枠(2026-08-08 追加)

**すべての状況報告の末尾に付ける。該当がなければ「なし」と書く** — 書けないなら何かある。

```
【気になる点】
- 気になること: <具体的に。なければ「なし」>
- 根拠が薄い箇所: <見立てのうち確認できていない部分>
- 判断が要る場面: <本人に決めてほしいこと。期限つきなら時刻も>
```

**次に該当したら必ず言う**(黙って進めない):

1. SL/TPが**帯の内側**にある → どの帯か、何回止められたか
2. 見ているデータが**部分的** → 「M1の60本だけ」等と明示。**上位足を見ずに方向を語らない**
3. **RRが1.2未満** → 「入らないが答え」と先に言う
4. **本人の見立てと割れている** → 数字で差を出す(黙って従わない)
5. **原則から外れる**提案をしようとしている → どの原則のどこに反するか
6. **締め切りが近い**(指標・週末クローズ) → 残り時間と、要る判断
7. 前回の報告から**前提が変わった** → 何が変わったか

**「どうされますか」で終えない**。推奨を先に出し、本人が否定だけすればよい形にする。

### 従来の報告様式

- ダイジェスト: `**定期報告(HH:MM)**: USDJPY xxx.xx(±X.Xpips/幅X.X) 含み損益±x,xxx円 / 金 x,xxx(±X.X/幅X.X) / 玉N SL:xxx.xx / 特記事項`
  - **変動の表記(2026-08-07 追加、本人要望)**: watcherのDIGEST行が `銘柄:現在値(区間の増減/幅N)` を出すようになった。**その数字をそのまま転記する**(自分で計算しない)。単位はUSDJPYがpips、金がドル。増減は前回ダイジェストからの変化、幅はその15分間の高安差
  - 幅が小さい(USDJPY 10pips未満など)なら「膠着」、大きいなら「変動中」と一言添えてよい
  - **含み損益は `runtime/latest_account.md` の Open Positions 各行の P/L を合計してそのまま転記する。pips を自分で計算しない**(2026-08-05 フォーマット改定: 軽量モデルの pips 計算で符号が反転した事故への対策。ショートは価格が建値より下=利益であり、価格差の符号と損益の符号は逆になる)
  - 玉N = ポジション数、SL: は現在のSL水準(建値なら「建値157.81」)。特記事項がなければ「特記なし」
- 執行報告: 何を・なぜ(どのルール)・結果(チケット・価格)・次の状態
- 時刻はウォッチャー出力のタイムスタンプをそのまま使う(推定時刻を書かない)
- **報告はチャットと同時に `runtime/ops_digest.log` にも1行追記する**(他セッションから `tail runtime/ops_digest.log` で参照可能にするため。2026-08-05 本人決定)。書式: `YYYY-MM-DD HH:MM:SS DIGEST USDJPY-m:xxx.xxx(±X.X/幅X.X) XAUUSD-m:xxxx.xx(±X.X/幅X.X) pos:N pl:±NNNN bal:NNNNNN note:...`(pl は Open Positions の P/L 合計、円) / 執行時は `EXEC ルール名 内容...` の行を追記
